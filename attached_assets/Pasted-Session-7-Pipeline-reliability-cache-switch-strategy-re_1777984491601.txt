Change 2 — Strategy resolver
After buildingType is read from the job record at line ~2016, add the strategy resolver immediately after:
typescripttype PipelineStrategy =
  | "schedule_primary"    // 100+ schedule entries — trust the schedule
  | "floor_plan_primary"  // no schedule — full vision + rules engine
  | "hybrid"              // schedule exists but < 100 entries — blend both
  | "egress_only";        // no usable floor plan files

function resolveStrategy(
  btKey: string | null,
  scheduleLength: number,
  floorPlanFileCount: number
): PipelineStrategy {
  if (scheduleLength >= 100) return "schedule_primary";
  if (floorPlanFileCount === 0) return "egress_only";
  if (scheduleLength > 0) return "hybrid";
  return "floor_plan_primary";
}
Call it right after files are loaded (after floorPlanFiles is built, before Step 2):

  `[pipeline] Strategy: ${pipelineStrategy} — ` +
  `buildingType=${job.buildingType}, ` +
  `scheduleRows=${signSchedule.length}, ` +
  `floorPlanFiles=${floorPlanFiles.length}`
);
Important: resolveStrategy is called after Step 3a (sign schedule extraction) which populates signSchedule. The call site must be after Step 3a completes but before Step 9. Check where signSchedule is first populated and place the resolver call immediately after that.
