## FIX 1: Building Type Detection (HIGH PRIORITY)

The pipeline must auto-detect whether a project is residential, commercial, school,
hospital, hotel, etc. because the rules engine applies different rules per type.

In `artifacts/api-server/src/lib/pipeline.ts` or `rules-engine.ts`, add this function
and call it during the buildInventory step (after rooms are extracted, before rules run):

```typescript
export function detectBuildingType(rooms: Array<{ roomName: string }>, metadata?: { occupancyGroup?: string }): string {
  const allNames = rooms.map(r => r.roomName.toUpperCase()).join(" ");

  // Explicit metadata wins
  if (metadata?.occupancyGroup) {
    if (metadata.occupancyGroup.startsWith("R")) return "residential";
    if (metadata.occupancyGroup.startsWith("E")) return "school";
    if (metadata.occupancyGroup.startsWith("I-2")) return "hospital";
    if (metadata.occupancyGroup.startsWith("A")) return "church";
    if (metadata.occupancyGroup.startsWith("S") || metadata.occupancyGroup.startsWith("F")) return "warehouse";
  }

  // Room name keyword detection
  const unitCount = rooms.filter(r => r.roomName.toUpperCase().startsWith("UNIT")).length;
  if (unitCount > rooms.length * 0.3) return "residential";

  if (/PATIENT|NURSE STATION|EXAM ROOM|ICU|OPERATING/.test(allNames)) return "hospital";
  if (/CLASSROOM|GYMNASIUM|CAFETERIA|PRINCIPAL|GYMNASIUM/.test(allNames)) return "school";
  if (/GUEST ROOM|FRONT DESK|HOUSEKEEPING|CONCIERGE/.test(allNames)) return "hotel";
  if (/NAVE|SANCTUARY|ALTAR|PARISH|FELLOWSHIP/.test(allNames)) return "church";
  if (/CLEAN ROOM|FUME HOOD|BSL-|LAB BENCH/.test(allNames)) return "lab";
  if (/VAULT|TELLER|SAFE DEPOSIT/.test(allNames)) return "bank";
  if (/LOADING DOCK|SHIPPING|ASSEMBLY LINE|FORKLIFT/.test(allNames)) return "warehouse";
  if (/MERCHANDISE|FITTING ROOM|STOCK ROOM/.test(allNames)) return "retail";

  return "commercial"; // default
}
```

Save the detected building type to `jobs.buildingType` in the database.

## FIX 3: Multi-Building Support — R17 (HIGH PRIORITY)

The NOVO Riverside project has TWO buildings (292 Baker + 294 Baker) that must
be tracked independently. Each building needs its own subtotals.

In the pipeline `buildInventory` step, detect multiple buildings by:

1. Looking for rooms with different building prefixes (292-xxx vs 294-xxx)
1. Or looking for multiple “BUILDING” labels on the drawing index

In `artifacts/api-server/src/lib/pipeline.ts` buildInventory step:

```typescript
// Detect buildings from room number prefixes like "292-101" or building labels
function detectBuildings(rooms: ExtractedRoom[]): string[] {
  const prefixes = new Set<string>();
  for (const room of rooms) {
    // Match building prefix patterns: "292", "294", "BLDG-A", "BUILDING 1"
    const m = room.roomNumber.match(/^(\d{3})-/) || 
              room.roomName.match(/^(BUILDING|BLDG)\s*([A-Z0-9]+)/i);
    if (m) prefixes.add(m[1]);
  }
  return prefixes.size > 1 ? Array.from(prefixes) : ["main"];
}
```

Store `buildingId` on each room and sign. The sign schedule export should group
by building with separate subtotals per building.

## FIX 8: Confidence Scoring — Rules-Based Signs Should Be High Confidence (MEDIUM PRIORITY)

Signs assigned by the deterministic rules engine (R1-R17) should have high
confidence (≥85%). Currently they may be getting lower scores.

In the rules engine confidence computation:

```typescript
function computeConfidence(sign: SignAssignment, room: RoomInventory, overrides: RuleOverride[]): number {
  // Rules-based assignment = high confidence
  if (sign.source === "rule_engine") {
    // Check if a tenant override confirms this assignment → 95%
    if (overrides.some(o => matchesCondition(room, o.condition))) return 0.95;
    // Standard rule application → 85%
    return 0.85;
  }
  // LLM-assisted → lower confidence
  if (sign.source === "llm") return 0.65;
  // Manual → confirmed
  if (sign.source === "manual") return 1.0;
  return 0.70;
}
```

## FIX 9: Stair & Elevator Signs — These Are Not Per-Room (LOW PRIORITY)

Stairs and elevators are “non-room entities” — they need signs but don’t appear
as rooms in the room inventory. They need special handling.

In the pipeline’s `applyRules` step, after processing all rooms, add:

```typescript
// Apply stair rules (R11): find all stair entries in rooms
const stairs = rooms.filter(r => r.isStair);
for (const stair of stairs) {
  const traits = BUILDING_TRAITS[buildingType];
  if (traits.stairMode === "separate") {
    // Add Stair (Corridor) and Stair (Landing) as separate signs
    signs.push({ signType: "Stair (Corridor)", qty: stair.corridorEntries || 1, ruleRef: "R11" });
    signs.push({ signType: "Stair (Landing)", qty: 1, ruleRef: "R11" });
  } else {
    // Combined: corridorEntries + 1 landing
    const qty = (stair.corridorEntries || 1) + 1;
    signs.push({ signType: "Stairs (C+L)", qty, ruleRef: "R11" });
  }
}

// Apply elevator rules (R12): per building or per level
const elevators = rooms.filter(r => r.isElevator);
for (const elev of elevators) {
  if (traits.elevatorMode === "per_building") {
    signs.push({ signType: "In Case of Fire", qty: 1, ruleRef: "R12" });
  } else {
    // per_level: one sign per level the elevator serves
    signs.push({ signType: "Elevator", qty: levelCount, ruleRef: "R12" });
  }
}
```
