What's broken: analyzeSheet() returns room coordinates relative to the full rasterized image including title block, construction notes, and sidebar. The floor plan drawing occupies only a portion of the image — so markers land in the title block area instead of on the actual rooms.
What changes: pipeline.ts only — analyzeSheet() Gemini prompt and coordinate conversion. No other files touched.
The fix — two-pass Gemini prompt:
Replace the current single prompt with a two-pass approach in one Gemini call using a structured prompt:
You are analyzing a floor plan image. Complete two tasks:

TASK 1 — Find the drawing boundary:
Identify the bounding box of the actual floor plan drawing area, 
excluding title blocks, construction notes, legend boxes, north arrows, 
and any text-heavy sidebar panels.
Return as:
{
  "drawingBounds": {
    "x1_pct": 0.05,
    "y1_pct": 0.12,
    "x2_pct": 0.78,
    "y2_pct": 0.88
  }
}
Where x1/y1 is top-left corner and x2/y2 is bottom-right corner 
of the drawing area, as fractions of the full image dimensions.

TASK 2 — Find room door positions:
Within the drawing area identified above, locate each visible room 
label and return the position of its door opening.
Return coordinates as fractions of the FULL IMAGE (not the drawing 
area) so they can be directly converted to the 0–100,000 grid.

Return a single JSON object only — no markdown, no explanation:
{
  "drawingBounds": {
    "x1_pct": 0.05,
    "y1_pct": 0.12, 
    "x2_pct": 0.78,
    "y2_pct": 0.88
  },
  "rooms": [
    {
      "roomNumber": "A215",
      "door_x_pct": 0.312,
      "door_y_pct": 0.461,
      "door_side": "left",
      "door_type": "hinged",
      "confidence": 0.95
    }
  ]
}

Rules:
- roomNumber exactly as printed (A215, B209, CORRIDOR, 60.1.128)
- door_x_pct / door_y_pct relative to FULL IMAGE dimensions
- door position = the door opening on the wall, not room center
- Only include rooms with clearly readable labels inside the drawing bounds
- Omit rooms with confidence below 0.7
