Fix 1 — Pricing tab material override not firing
Root cause: The new Gemini prompt that extracts materialSpec only runs in the Gemini fallback branch (when text extraction returns fewer than 3 rows). When the sign schedule has machine-readable text and yields ≥3 rows, the text path is taken, Gemini is skipped, and jobMaterialSpec stays null.
The fix: After the text path succeeds (≥3 rows), add a separate lightweight Gemini Flash call just for material spec extraction. This call is fast and cheap — it only returns the materialSpec object, not entries.
In pipeline.ts, find the text path branch around line 3443 where textEntries.length >= 3 triggers the text path. After that branch sets sheetEntries = textEntries, add:
typescript// Text path succeeded — still extract material spec via lightweight Gemini call
if (jobMaterialSpec === null) {
  try {
    const specPrompt = `This is an architectural sign specification sheet.
Extract only the project-wide material specification as a JSON object:
{
  "substrate": "the substrate material (e.g. photopolymer, aluminum, acrylic, ADA plastic)",
  "finishMethod": "the finish or print method (e.g. direct UV print, painted, brushed, raised copy)",
  "brailleSpec": "Braille requirement (e.g. Grade 2 Braille, no Braille)",
  "mountingHeight": "mounting height if specified (e.g. 60 inches AFF)",
  "manufacturer": "sign manufacturer or series if called out"
}
If a field is not found use null.
Respond with JSON only. No markdown. No preamble.`;

    const specResponse = await geminiAi.models.generateContent({
      model: "gemini-2.5-flash",
      contents: [{ role: "user", parts: [
        { inlineData: { mimeType: "image/png", data: rasterizedPage } },
        { text: specPrompt }
      ]}]
    });

    const specText = specResponse.candidates?.[0]?.content?.parts?.[0]?.text ?? "";
    const specParsed = JSON.parse(specText.replace(/```json|```/g, "").trim());
    if (specParsed && typeof specParsed === "object") {
      jobMaterialSpec = {
        jobId,
        substrate:      specParsed.substrate ?? null,
        finishMethod:   specParsed.finishMethod ?? null,
        brailleSpec:    specParsed.brailleSpec ?? null,
        mountingHeight: specParsed.mountingHeight ?? null,
        manufacturer:   specParsed.manufacturer ?? null,
        source:         "sign_schedule",
      };
    }
  } catch {
    // Non-blocking — material spec extraction failure doesn't affect sign generation
  }
}
Note: rasterizedPage is already available in this scope from the earlier rasterization call. If it isn't in scope at this exact point, move the material spec call to just after the existing rasterization in the text path branch, before sheetEntries is assigned.
