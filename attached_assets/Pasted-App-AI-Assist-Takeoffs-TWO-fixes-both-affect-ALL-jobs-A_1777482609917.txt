FIX 3 — Normalize floor label casing
         "Level 1" vs "LEVEL 1" duplication
         Affects ALL plans, ALL building types
════════════════════════════════════════════════
Both cases exist in DB causing duplicate floor
tabs and incorrect floor counting.

Normalize to uppercase "LEVEL N" everywhere:

  function normalizeFloor(label: string|null) {
    if (!label) return null;
    const t = label.trim();
    // "Level 1", "level 1", "LEVEL 1" → "LEVEL 1"
    const m = t.match(
      /^(level|floor|fl|story|l)\s*[-–]?\s*(\w+)$/i
    );
    if (m) return \`LEVEL \${m[2].toUpperCase()}\`;
    if (/^\d+$/.test(t)) return \`LEVEL \${t}\`;
    return t.toUpperCase();
  }

Apply on INSERT to signs table.
Apply on INSERT to sheet_cache.
Apply in XLSX export floor column.
Apply in Plans tab floor selector grouping.

Fix existing data:
  UPDATE signs SET floor_label =
    UPPER(REGEXP_REPLACE(
      floor_label,
      '^(Level|Floor|FL)\s+',
      'LEVEL ',
      'i'
    ))
  WHERE floor_label IS NOT NULL
  AND floor_label != UPPER(floor_label);
