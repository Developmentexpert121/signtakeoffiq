Fix — Two-pass extraction for image-based schedule sheets
Replace the single Gemini call in the 300 DPI retry with a two-pass approach:
Pass 1 — Table location pass (fast, cheap):
Send the full page image with a short prompt asking Gemini to identify where the schedule table is and whether it spans the full page or occupies a sub-region:
"This is an architectural drawing sheet. Does it contain a signage schedule table (a table with columns like Room Number, Room Name, Sign Text)? If yes, answer with JSON: { \"hasTable\": true, \"tableRegion\": \"full\" | \"left\" | \"right\" | \"top\" | \"bottom\", \"estimatedRows\": number }. If no table is found: { \"hasTable\": false }. JSON only, no preamble."
Pass 2 — Extraction pass:
Use the tableRegion from Pass 1 to decide what to send:

"full" → send the full 300 DPI image with the extraction prompt
"left" → crop to left 45% and send cropped image
"right" → crop to right 45%
"top" / "bottom" → crop accordingly

For the extraction prompt in Pass 2, use:
"This image contains a signage schedule table with columns for Room Number, Room Name, and Sign Text. Extract every row as a JSON array: [{ \"roomNumber\": string, \"roomName\": string, \"signType\": string, \"quantity\": number }]. Include ALL rows — there may be 200–400 entries across multiple columns or table sections. If a room has multiple sign types, create one entry per sign type. Return JSON array only. No markdown. No preamble."
If Pass 1 returns hasTable: false, skip Pass 2 entirely and log:
[Step 3a] ${sigSheet.sheetId}: Pass 1 found no table — skipping extraction
Log the region detected:
[Step 3a] ${sigSheet.sheetId}: Pass 1 — tableRegion="${region}", estimatedRows=${n}
This works for any sheet layout — full-width tables, left-side tables, right-side tables — without any hardcoded geometry assumptions.
