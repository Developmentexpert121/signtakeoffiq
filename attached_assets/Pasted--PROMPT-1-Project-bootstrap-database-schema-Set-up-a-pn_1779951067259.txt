 PROMPT 1 — Project bootstrap & database schema
Set up a pnpm monorepo with three artifacts: a React + Vite web app (artifacts/web), an Express + TypeScript API server (artifacts/api-server), and a shared lib/db package using Drizzle ORM + PostgreSQL.

Create the following Drizzle schema tables in lib/db/src/schema/:

tenants — id (text, pk), name, slug (unique), plan (text, default 'free'), externalCompanyId (nullable, unique), createdAt, updatedAt.

users — id (text, pk), tenantId (fk → tenants.id, nullable for super_admin), email (unique, lowercase), fullName, role (enum: 'super_admin' | 'owner' | 'user', default 'user'), passwordHash (nullable for pending), externalId (nullable, unique), companyId (nullable), phone, username, jobTitle, location, createdAt, updatedAt.

invitations — id (text, pk), tenantId (nullable — owner invites create tenant on accept), email, role, ownerId (fk → users.id, who sent it), tokenHash (sha256), expiresAt, acceptedAt (nullable), createdAt. Index on (email, tenantId) and tokenHash.

sessions — id (text, pk), userId (fk → users.id, cascade delete), tokenHash, userAgent, ipAddress, expiresAt, lastSeenAt, createdAt. Index on tokenHash and userId.

Provide a Drizzle config, migration command, and a seed.ts that inserts one super_admin and one demo tenant + owner.

📋 PROMPT 2 — Authentication & session middleware
Implement session-based authentication in artifacts/api-server:

POST /api/auth/login — verify email + password (bcrypt), create a session row, return Set-Cookie: session=<token>; HttpOnly; Secure; SameSite=Lax.
POST /api/auth/logout — delete the session row and clear the cookie.
GET /api/auth/me — return the current user from the session.
POST /api/auth/change-password — require current password, validate new password strength, update passwordHash, invalidate all other sessions for that user.
Create a lib/tenantAuth.ts middleware module exporting:

requireAuth(req, res, next) — loads session, attaches req.ctx = { userId, tenantId, role }. 401 if missing/expired. Updates sessions.lastSeenAt.
requireSuperAdmin — 403 unless role === 'super_admin'.
requireOwnerOrAbove — allows super_admin and owner.
requireAdmin — alias of requireOwnerOrAbove (accepts legacy 'admin' value too).
All non-super_admin queries must be tenant-scoped via req.ctx.tenantId. Add a helper scopeToTenant(query, ctx) that injects the WHERE clause.

📋 PROMPT 3 — User management API routes
Create artifacts/api-server/src/routes/userManagement.ts with:

GET /api/users — requireOwnerOrAbove. Super_admin sees all users across tenants; owner sees only users in their tenant. Returns id, email, fullName, role, tenantId, createdAt.
POST /api/users/:id/reset-password — requireOwnerOrAbove. Owner can only reset users in their tenant and only user role. Generates a temporary password, returns it once (do not log).
DELETE /api/users/:id — requireOwnerOrAbove. Same tenant scoping. Block deletion of self and last owner of a tenant.
Add unit tests with Vitest covering: cross-tenant access denied (403), owner cannot delete another owner, super_admin can delete any user, cannot delete self.

📋 PROMPT 4 — Invitations API & accept flow
Create artifacts/api-server/src/routes/invitations.ts:

POST /api/invitations — requireOwnerOrAbove. Body: { email, role }. Owner can only invite 'user'; super_admin can invite 'owner' (auto-creates a new tenant) or 'user'. Generates a 32-byte token, stores sha256 hash, returns the plaintext token in the invite URL once. Sends email via the configured provider (stub with console.log if none).
GET /api/invitations — list pending invites scoped by tenant/role.
DELETE /api/invitations/:id — revoke pending invite.
GET /api/invitations/lookup/:token — public. Returns { email, role, tenantName } if token is valid and not expired/accepted.
POST /api/invitations/accept — public. Body: { token, fullName, password }. Creates user (or attaches to tenant), creates first session, sets cookie, marks invite acceptedAt. For owner invites with no tenant, create the tenant here.
Tokens expire in 7 days. Add tests for: expired token, already-accepted token, wrong email, owner invite tenant creation.

📋 PROMPT 9 — SSO / external provisioning webhook (optional)
Create POST /api/internal/provision-user protected by a shared secret header X-Internal-Token (env var INTERNAL_PROVISIONING_SECRET).

Body: { action: 'upsert' | 'delete', externalId, email, fullName, role, externalCompanyId, companyName }.

On upsert: find-or-create tenant by externalCompanyId, then upsert user by externalId. Update role, fullName, email.

Return { ok: true, userId, tenantId }. Never expose this route through the auth middleware.
