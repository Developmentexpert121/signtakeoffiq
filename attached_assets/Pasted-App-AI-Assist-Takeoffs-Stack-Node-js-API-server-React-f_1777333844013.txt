BUG 1 — Overview shows 0 signs after force rescan
──────────────────────────────────────────
In artifacts/api-server/src/routes/jobs.ts (or 
wherever the Overview job stats are computed):

The totalSigns count on the Overview tab is reading 
from a cached/stale field on the jobs table that 
resets to 0 at the start of a force rescan and may 
not be updated until processing fully completes.

Fix:
1. Create or update a GET /api/jobs/:jobId/counts 
   endpoint that queries the signs table LIVE:

   SELECT 
     COUNT(*) as totalSigns,
     COUNT(*) FILTER (WHERE confidence >= 75) as highConfidence,
     COUNT(*) FILTER (WHERE confidence < 75 AND dismissed = false) as needsReview
   FROM signs
   WHERE job_id = $1 AND dismissed = false

2. In artifacts/web/src/pages/job-detail.tsx:
   The Overview tab metric cards (Total Signs, 
   High Confidence, Needs Review) must call 
   /api/jobs/:jobId/counts — NOT read from 
   job.totalSigns on the job record.
   
   This ensures Overview always matches Review tab.

3. Do NOT change the Review tab — it already 
   shows the correct count. Just make Overview 
   use the same live query.
